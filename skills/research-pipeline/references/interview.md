# Интервью

Цель — превратить «поищи про X» в задачу, по которой можно и собирать, и потом принять результат.

Правила:
- Два круга, в каждом 3–5 вопросов.
- У каждого вопроса — 2–4 варианта и твоя рекомендация первой.
- Ответ, который можно вывести из запроса, не спрашивай: впиши в карточку и покажи, пользователь поправит.

## Круг 1 — работа (до разведки)

1. **Какое решение вы примете по итогам?**
   - Варианты по контексту: «выбрать инструмент», «найти людей для коллаборации», «понять рынок перед запуском курса», «собрать базу, к которой будем возвращаться».
   - Цель-тема («про ИИ-преподавателей») — не ответ: переспроси, что изменится после ресерча.
2. **Что нужно на выходе?**
   - `list` — список с короткой оценкой;
   - `compare` — таблица для сравнения по полям;
   - `findings` — база находок с заметкой на каждую;
   - `answer` — ответ на вопрос со ссылками;
   - `method` — методика.

   Рекомендация по цели: выбрать → `compare`; возвращаться → `findings`.
3. **Что считается одной строкой?** Предложи единицу анализа из словаря `kind`: «человек, а не его аккаунты», «курс, а не автор», «репозиторий». Если в теме смешаны виды, выбери главный, остальные пойдут связями.
4. **С чего стартуем?**
   - `topic` — тема, ищем с нуля;
   - `list` — у пользователя есть список или датасет;
   - `source` — конкретный аккаунт, сайт или канал, который надо перебрать;
   - `question` — вопрос, на который нужен ответ.

   Есть материалы — попроси сразу.
5. **Бюджет и глубина.** Варианты:
   - «быстро: до 50 объектов, час»;
   - «стандарт: до 300, вечер»;
   - «глубоко: до 1000, ночной прогон».

   Плюс есть ли деньги на платные инструменты.

## Круг 2 — предмет (после разведки)

Вопросы строятся на том, что показала разведка: какие площадки и каталоги нашлись, какой там шум, какой объём.

1. **Критерии.** Предложи 3–6 «по делу» и 3–6 «мимо», каждый проверяемый за минуту.
   - Хорошо: «преподаёт на русском», «есть платный продукт или регулярный бесплатный контент», «публиковался после 2025-06».
   - Плохо: «качественный», «интересный».
2. **Периметр:** языки, страны, период, площадки. Обязательно хотя бы одно исключение: что сознательно не берём.
3. **Приёмочные вопросы.** Предложи 8–12 кандидатов, пусть пользователь оставит 5–10. Хороший вопрос проверяем по базе: «кто из найденных продаёт курс дороже 30 тыс. ₽ и сколько их», «какие площадки дают больше всего полезного». Плохой — «что интересного в теме».
4. **Известные объекты.** «Назовите 5–10, которые точно должны найтись». Пользователь не может — предложи из разведки с пометкой «предложено агентом». В поиск их не подставлять: по ним меряется полнота.
5. **Схема полей.** Из приёмочных вопросов выведи поля (имя, тип, единица, допустимые значения, на какой вопрос отвечает, какой уровень проверки нужен) и покажи таблицей. Поле, которое ни на что не отвечает, — вычеркнуть.

## Карточка готова, когда

- [ ] цель — это решение, а не тема;
- [ ] единица анализа одна;
- [ ] по критериям судьбу объекта можно решить за минуту;
- [ ] в периметре есть хотя бы одно исключение;
- [ ] каждый приёмочный вопрос проверяем по базе;
- [ ] у каждого поля схемы непустой `answers`;
- [ ] есть известные объекты, или пользователь явно отказался (тогда полнота в отчёте — «не измерена»);
- [ ] у бюджета есть потолок.
