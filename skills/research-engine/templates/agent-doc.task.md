# Задача `{{LABEL}}` — `AGENT.md`, вход для агента

Ты пишешь `{{OUT_PATH}}` — первый файл, который открывает агент, попавший в движок «{{TITLE}}». Его задача: за одно чтение объяснить, куда агент попал, что открыть следующим и чего не делать.

## 1. Миссия движка

{{MISSION}}

**Внутри периметра:** {{PERIMETER_IN}}

**Вне периметра:** {{PERIMETER_OUT}}

Сегодня **{{TODAY}}**. Язык документа — `{{LANGUAGE}}`.

## 2. Что читать перед написанием

- `{{ROOT}}/METHOD.md` — **целиком**. Это источник: `AGENT.md` даёт вход в методику и своих правил не вводит. Расхождение между двумя файлами — брак.
- `{{ROOT}}/synthesis/GAPS.md` — раздел про границу применимости, целиком.
- Своды — по оглавлениям (`grep -n '^#'`), чтобы одной строкой описать, за чем в каждый ходят:

{{ALL_SYNTHESIS}}

## 3. Структура файла

Держись в 60–100 строках. Это карточка на входе, а не вторая методика.

1. **Одним абзацем: куда ты попал.** Что за движок, какую работу агент по нему делает и почему нужно работать по нему, а не по своим представлениям о предмете.
2. **Периметр.** Что внутри, что вне — одной строкой каждое. Агент должен сразу понять, когда движок не его инструмент.
3. **Что читать и когда.** Таблица: шаг | файл | когда открывать | что там лежит. Первая строка всегда — `METHOD.md`, целиком, до первого действия. Последняя — что читать не надо: сырьё конвейера (`reports/`, `prompts/`, `state/`) нужно только при пересборке движка.
4. **Правило окна.** Как читать большие файлы: оглавление через `grep -n '^#'`, дальше Read с offset/limit по нужному диапазону; `INDEX.md` даёт номера строк разделов; читать свод целиком не надо и вредно — окно кончится раньше работы. Здесь же: за цифрой идти в банк фактов, а не в память.
5. **Порядок работы кратко.** Шесть-восемь пунктов сквозной процедуры из `METHOD.md` с указанием, где искать полную версию. Пересказ, а не новая процедура.
6. **Правила, которые нарушают чаще всего.** Три-пять законов из ядра методики, в формулировке действия, с последствием нарушения.
7. **Если работаешь командой субагентов.** Роли по процедуре, какой файл читает каждая, каким артефактом роли обмениваются. Отдельно — правило: фактура передаётся явным файлом, роли не выдумывают того, чего в нём нет.
8. **Чего движок не делает.** Честная граница из `GAPS.md` плюс ссылка на её полную версию.

## 4. Тон

Плотно, инструктивно, во втором лице. Правило действия вместо наблюдения. Никаких обещаний без источника, канцелярита, «важно отметить», «ключевой инсайт», оборота «не X, а Y», эмодзи в заголовках. Каждая строка таблицы обязана экономить агенту чтение.

## 5. Последнее действие

Последним действием запиши структурированный результат в файл `{{RESULT_PATH}}` (JSON, UTF-8) и верни этот же объект в ответе. Поля:

- `path` — абсолютный путь записанного файла;
- `summary` — 3–5 предложений: что внутри и как устроен вход;
- `sections` — список разделов файла;
- `factsCarried` — сколько адресов (файл + когда открывать) вынесено в таблицу чтения;
- `approxWords` — примерный объём файла в словах;
- `openIssues` — расхождения с `METHOD.md` и места, где вход пришлось упростить (пустой массив, если таких нет).

Файл результата пишешь ты сам — без него задача считается невыполненной.
