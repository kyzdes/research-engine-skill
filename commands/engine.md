Пользователь вызвал движок ресерча с аргументом: `$ARGUMENTS`

Загрузи скилл `research-engine` (Skill tool) и работай по нему. `$SKILL` ниже — каталог скилла (Base directory из его загрузки). Аргумент читается так:

- `new <тема>` — стадия 0: бриф по `references/BRIEF.md` (прочитай его целиком). Заведи каркас `engine-init.mjs --request "<тема дословно, как написал пользователь>"`, первым сообщением покажи разбор запроса (как понял, допущения, размытые слова), запусти разведку (`render-tasks.mjs --stage recon` и `synthesis.mjs` со `stage: "recon"`) в фоне и задай первый круг вопросов о работе базы через AskUserQuestion. Второй круг — по `brief/RECON.md`. Заполни `brief`, `mission`, `perimeter` в `engine.json`, `brief.mjs --write`. Останов: `BRIEF.md` утверждает пользователь.
- `brief` — `node $SKILL/scripts/brief.mjs --root <root>`: готов ли бриф, какие контрольные вопросы не закрыты темами, что спросить у пользователя. Используй и тогда, когда задача базы поменялась посреди сборки.
- `plan` — стадия 1: декомпозиция, только по утверждённому брифу. Тема режется на ТЗ, пишутся `prompts/`, `synthesis-spec/` и карта «тема → свод»; каждая тема получает `answers` — id контрольных вопросов. Список тем и таблица «контрольный вопрос → темы» показываются пользователю до прогона.
- `run <stage>` — прогон стадии (`research`, `verify`, `synth`, `merge`, `critique`, `method`, `agent-doc`). Сначала `render-tasks.mjs`, затем исполнитель: в Claude Code — Workflow-скрипт из `<root>/workflows/` (`verify` — это `research.mjs` с `args.stage: "verify"`), в Codex — `fanout.mjs`. Партиями, а не всё разом. После каждой партии — `status.mjs --write`, затем `audit.mjs`.
- `audit` — `audit.mjs` по корню движка, разбор блокеров и предупреждений.
- `index` — `build-index.mjs`: карта сводов с номерами строк.
- `status` — `node $SKILL/scripts/status.mjs --root <root>`: что собрано по диску, где `engine.json` расходится с диском, что упало и какая команда следующая. Покажи это пользователю вместе с последними строками `state/run-log.md`. Статусы записывай (`--write`) после того, как показал расхождения.

Без аргумента — покажи статус текущего движка, если он есть в этом каталоге, иначе объясни, с чего начать.
